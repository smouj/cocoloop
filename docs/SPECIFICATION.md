# CL Studio — Product & technical specification

## Identity and principle

**Name:** CocoLoop (CL Studio). **Type:** DAW: Digital Audio Workstation. **Category:** original local-first music sequencer and audio editor with agent-native tools. **Target:** desktop users, producers, hobbyists, makers and software agents. **Language:** English product labels with Spanish helper copy in the alpha; full Spanish/English localization is on the roadmap.

**Version:** 0.2.0 alpha (2026-11-09). The repository, CI, security headers and browser test are part of the delivered product, not future claims.

**Design:** purpose-built, dark restrained color palette (deep-blue-charcoal, lime-green highlight with subtle warm orange accents, instrument-color accents), original coconut and sound-disc visual identity, low clutter, dense professional work surface. Reference workflow concepts: playlist, step sequencer, piano roll, mixer — common DAW functions. No copyrighted graphical replicas, factory samples or proprietary code.

## User journeys

### Human composer

Open a project → preview instruments → toggle drum steps / edit MIDI notes → arrange pattern clips → set mix levels/filters → play → export WAV / MIDI → save project.

### Codex / OpenClaw agent

Launch studio and open in browser → user enables editing → agent retrieves state/track IDs → agent submits structured action batch → application validates all operations → changes appear in the UI and undo history → agent receives actual applied or rejected status → user listens and saves.

## Initial architecture

- **Presentation:** native browser modules, no front-end external dependencies.
- **Project model:** JSON schema with bounded numbers, safe normalized arrays, track and clip IDs, immutable transactional action application.
- **Audio:** lookahead scheduler using Web Audio `AudioContext`, offline file rendering using `OfflineAudioContext`, 16-step repeating instrument patterns per bar.
- **Bridge:** Python stdlib HTTP listener local to loopback, in-process command queue; bearer-token for agent writes, same-origin for browser state and acknowledgements. MCP JSON-RPC stdio via Python bridge; CLI adapter for other agents.
- **Storage:** project JSON export; browser localStorage autosave except sample blobs.
- **Licensing:** original code MIT, dependent on local Python interpreter and browser. No API costs for app functionality.

## Agent action schema — v1

All actions have a mandatory `type`. There are no shell, network, URL, binary download, or arbitrary file path actions.

| type | fields | constraints |
|---|---|---|
| set_tempo | `bpm` | Integer 40–260 |
| set_title | `title` | Nonempty string, max 120 |
| set_bars | `bars` | Integer 1–32 |
| set_master | `volume` | 0–1 |
| add_track | `instrument`, `name?`, `id?` | Known instrument, max 32 tracks; explicit stable alphanumeric ID possible |
| delete_track | `track_id` | Must exist |
| rename_track | `track_id`, `name` | Max 90 chars |
| set_step | `track_id`, `step`, `enabled` | Step 0–15 |
| set_steps | `track_id`, `steps` | list of unique 0–15 steps (overwrites current) |
| add_note | `track_id`, `pitch`, `start`, `length?`, `velocity?` | Synth only, MIDI 0–127, 0–15 start, 1–16 length, 1–127 velocity |
| remove_note | `track_id`, `pitch`, `start` | exact note start |
| set_track | `track_id`, `field`, `value` | volume 0–1, pan -1–1, cutoff 200–18000, delay 0–1, mute/solo boolean |
| set_clip | `track_id`, `bar`, `enabled` | Bar 0–bars-1 |
| clear_track | `track_id` | Wipes track steps and notes only |

The `cl_apply_actions` tool takes up to 64 ordered actions; all are validated on a candidate project before commit. A failure returns `rejected` and does not alter the project. Browser undo can reverse an entire transaction.

## Delivered in 0.2.0

- Master fader wired to `set_master`; metronome with per-bar accent, excluded from offline renders.
- Note velocity selection for new MIDI notes.
- Duplicate-track command in the Inspector, preserving pattern, notes, clips, mixer values and sampler data.
- WAV encoder extracted as a pure function with header tests.
- MIDI melodic channels skip the General MIDI drum channel.
- Browser smoke test and documentation screenshots generated by Playwright.
- CSP, `nosniff`, `DENY` framing, no-referrer and permissions policy on static and API responses.
- Directory listing disabled.

## Explicit non-goals for 0.2

- No embedded agent chat, no bundled model, no accounts and no cloud sync.
- No native installer, VST hosting, audio recording or ASIO-class latency.
- No claim of production-grade mixing, mastering or loudness compliance.

## Stability and security milestones

Important pre-v1 items: automated audio golden tests, transport sync across browsers, per-project concurrency controls, robust handling of unexpected sample decoding errors, threaded native DSP that avoids garbage collection pauses, path-safe file operations, VST isolation, authorization review, CSP for all static assets, system dependency/license scanning and release signing policy.

## Definition of success

- 0 € core runtime and no required remote services.
- Users can hear, edit, save, load and export actual music.
- Agents can manipulate exactly the same state through a documented and restricted command schema.
- Every acknowledged agent write is visible and reversible.
- Default-deny permissions for agent mutation.
- Project formats are documented, portable and versioned.
- Roadmap claims are never represented as existing features.
